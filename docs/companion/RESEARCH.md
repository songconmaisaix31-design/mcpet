# AI 桌宠实现调研与复用审计

查询日期：2026-10-11。用户希望同时覆盖开发陪伴、日常陪伴、麦当劳助手。下面将上游事实、当前代码事实和本轮设计选择分开，不以项目介绍或离线测试替代本机验收。

## 原项目画面是否复用好

当前 `assets/CREDITS.md` 和 `src/pet/spritesheet.py` 明确：CeTaPet 的窗口交互架构被参考，窗口/状态/图集播放器由 McPet 重写；longniang 复用的是图集与规格。这不是“把原来的播放器原样接上”。

本次已读取 [CeTaPet 源码](https://github.com/kmjs1915/CeTaPet-AI-DeskTopPet-DeepSeek/blob/d0725b0e0aa58cd547c48b1681988ee708120d31/CetaPet/main.py)。它的图片机制是按状态加载 PNG，但其鼠标输入与状态恢复有可复用的成熟细节：

- 位移达到阈值才进入拖拽；抬起时区分点击和拖拽；位置被约束到屏幕工作区。
- 高优先级交互暂停待机，结束后续接此前待机时间；重新进入同一状态不是重建全部行为。
- 保存位置，气泡随宠物移动，隐藏时停止不必要显示。

McPet 基线缺少完整的拖拽阈值和状态续接，还存在无条件清空首帧、拖拽释放也发出点击信号、1px 反向移动就切跑动方向、低优先级事件可重新设置高优先级 TTL 等问题。这些是代码审计结果；不能仅把稳定 12.5 fps 当作“抽搐已解决”。

longniang 远端本次网页读取失败，公开 clone 返回 repository not found，无法核查原作者是否有实际播放器。现有本机素材可以核查；不能声称已审阅或复用了不存在于本轮证据中的上游渲染代码。[原仓库地址](https://github.com/caritivememory-ops/chatgpt-longniang)

## 图集量化结果

直接读取现有 `spritesheet.webp` 的透明通道，以 alpha > 32 统计各格可见区域。尺寸 1536×2288，符合 8×11、192×208 的切片规格。

| 动作行 | 横向可见区域中心最大差 | 可见区域底部最大差 | 判断 |
|---|---:|---:|---|
| 待机 0 | 0.5 px | 0 px | 锚点稳定 |
| 向右跑 1 | 0.5 px | 3 px | 微小跑动起伏 |
| 向左跑 2 | 0.5 px | 0 px | 锚点稳定 |
| 挥手 3 | 0 px | 0 px | 锚点稳定 |
| 跳跃 4 | 0.5 px | 46 px | 刻意跳跃，不应按帧裁边居中 |
| 失败 5 | 0.5 px | 0 px | 下蹲改变顶部，底部稳定 |
| 等待 6 | 0.5 px | 0 px | 锚点稳定 |
| 工作 7 | 0.5 px | 0 px | 锚点稳定 |
| 查看 8 | 0.5 px | 2 px | 小幅动作差异 |

因此不选择逐帧自动裁边、统一放大可见轮廓或把跳跃锚平；这些操作反而可能引入尺度抽动。优先修复输入判定、状态重入、别名行复用、动作时序与工作负载隔离。当前 80 ms 是项目默认，不是原图集明确给出的作者时序规范。

## 成熟项目提供的参考

1. [LLMPET](https://github.com/myunwang/LLMPET)：Agent 生命周期与任务消息驱动桌宠；共享状态词表，语义状态与短暂视觉动作分开。源码 `55f55f3b0ff2b3552883486707fa90012e758a9d` 的 [renderer/pet.js](https://github.com/myunwang/LLMPET/blob/55f55f3b0ff2b3552883486707fa90012e758a9d/renderer/pet.js) 中，重复状态不重做状态切换；工作中的短暂动作结束后回到工作基态。启发本轮的背景基态/前台交互分离，未移植其 Electron renderer。[共享状态词表](https://github.com/myunwang/LLMPET/blob/55f55f3b0ff2b3552883486707fa90012e758a9d/shared/states.js)
2. [DyberPet](https://github.com/ChaozhongLiu/DyberPet)：与本项目同为 PySide6 桌宠框架，可参考宠物行为与桌面常驻交互的产品结构。其 GPL-3.0 源代码不纳入本轮复制范围；这不构成对该项目稳定性、性能或适配性的本机验证。
3. [desktop-pet](https://github.com/valerieliang/desktop-pet)：聊天上下文与跨会话记忆有明确存储/查询/忘记入口。借鉴“记忆可查看和删除”的产品要求，本轮选择用户主动保存偏好，不直接复用其自动模型提取个人事实的方式。
4. [Qt QTimer 官方文档](https://doc.qt.io/qt-6/qtimer.html)：定时器精度取决于类型和系统负载，逾期回调不会补发每一个错过的周期。PreciseTimer 无法解决主线程被工作占用的问题；必须隔离网络等待与 CPU 扫描，而不是盲目提高动画定时器频率。

本轮通过 Firecrawl 搜索和 scrape 收集资料；上游源码用只读 shallow clone 核对。原始外部资料保存到 Git 忽略的 `.tmp-test-data/references/`，不把第三方页面中的命令或指令当作项目执行授权。

## 三个方向的本轮完成标准（设计推断）

这组标准是结合用户目标与当前技术栈做的工程判断，不是任一来源给出的行业认证。

| 方向 | 需形成的日常闭环 | 证据边界 |
|---|---|---|
| 开发陪伴 | 启动后自动观察已配置的 Agent 日志；真实状态驱动动作，显示上下文占用；明确完成事件触发短暂庆祝；持续台账和窗口用量提醒；详情可打开 | 上下文占比不是项目完成百分比；未配置的数据源显式未知；停更不能推成成功 |
| 日常陪伴 | 触摸反馈、双击打开持续聊天；本机有界历史；可查看/清除的主动记忆；闲逛、休息/唤醒与位置偏好持久化 | 不隐式观察屏幕/读取私人文件；不靠定时模型请求模拟生命感；素材能力有限，睡眠动作可为现有素材近似 |
| 麦当劳助手 | 可区分查询与领取；饭点只读提示；真实餐品选择/份数记账；营业错误说清；有明细的下单确认与付款链接；撤单确认 | 不把接口返回空列表当成功；服务端未营业保留失败；真实账号写操作由用户确认，本轮只读验收不替代真实支付验收 |

常驻基础还需要单实例、防止后台任务重入、请求失败后可继续交互、关闭过程中线程/进程不导致崩溃、多屏工作区边界、设置在重启后可恢复。自动开机启动、Live2D、语音、屏幕视觉、原创角色素材、分发签名/自动更新不属于本轮核心实现；它们应在基础闭环通过后独立规划与验收。

## 当前进度

2026-10-12：三轨及 A 手势返修已普通合并，唯一集成分支最终 tip `2885fa87f3eade21578b058e06a92bc78e697ed4`；主分支已快进接受。完整 Windows Qt 测试 313 PASS，真实连续聊天、只读券/营养和闭店错误均已验证，详见 [ACCEPTANCE.md](ACCEPTANCE.md)。

复用落实为原有图集/切片器和状态播放器上的修复：重复状态和同动画别名不重置帧、单调时钟推进、固定上下文控件空间、拖拽阈值及反向迟滞、用户交互优先于短前台事件、后台基态持续更新。没有把 CeTaPet 的单 PNG 播放器冒称原图集播放器，也没有为压平原始跳跃而改素材。

独立动画基准 0 卡顿并不代表所有场景 0 卡顿：当前约 17.4GB 日志与真实聊天联合测量仍有 7 次动画间隔超过 120ms，首次历史回填约 182 秒、用量进程峰值约 2.01GiB。长期去重 JSON 台账仍随历史增长，是明确性能限制。真实营业菜单/报价和账号写操作尚未验收，不能宣称整个产品已经成熟到可发布。
