## 安装与首次启动

### 选择安装方式

| 你的使用方式 | 下载或安装 | 需要准备 |
|---|---|---|
| Windows 桌面陪伴 | `McPet-v0.1.0-windows-x64.zip` | Windows x64，完整解压文件夹 |
| 在现有 Agent 中使用 | `McPet-v0.1.0-agent.zip` 或源码 | Python 3.10+，支持 MCP stdio 的宿主 |
| 从源码运行桌宠 | 克隆仓库，安装 `requirements.txt` | Python 3.10+，可运行 PySide6 的桌面环境 |

发行包在 [v0.1.0 下载页](https://github.com/songconmaisaix31-design/mcpet/releases/tag/v0.1.0) 的 Assets 区。选择上表中的文件名；GitHub 的 `Source code` 压缩包供源码使用。

### Windows 便携包

1. 解压 `McPet-v0.1.0-windows-x64.zip` 到固定位置。
2. 打开解压后的目录，双击 `Start-Pet.vbs`。
3. 新用户会看到 DeepSeek 娘；已有用户恢复保存的角色和皮肤。
4. 右键宠物 →「设置 → 查看设置」，了解饭点、咖啡时间和账号配置状态。
5. 右键 →「角色与动作」，试着切换套装或角色。

便携包带有运行环境，保留 `McPet.exe`、`_internal`、`Start-Pet.vbs` 的完整目录结构。启动脚本不可用时，在解压目录打开 PowerShell，运行：

```powershell
.\McPet.exe --desktop
```

`McPet.exe` 默认运行 stdio 服务；显示桌宠需要 `--desktop`。再次启动同一数据目录的桌面入口会唤醒已有实例。

### 从源码运行

在 PowerShell 中：

```powershell
git clone https://github.com/songconmaisaix31-design/mcpet.git
cd mcpet
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.main --desktop
```

macOS / Linux 的虚拟环境解释器位于 `.venv/bin/python`，在仓库目录使用：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m src.main --desktop
```

桌面版当前以 Windows 实际验证为主；macOS / Linux 的桌面和托盘兼容性需要分别核实。仅接入 Agent 时，将安装依赖改为 `requirements-agent.txt`，然后运行 `python -m src.agent_install`；虚拟环境用户使用对应的虚拟环境解释器。

## 桌面基本操作

| 操作 | 结果 |
|---|---|
| 按住左键拖动 | 移动宠物，松开后保存位置 |
| 单击宠物 | 打招呼，提示右键入口 |
| 双击宠物 / 点击托盘图标 | 恢复宠物并提示操作入口 |
| 右键宠物 / 托盘图标 | 打开功能菜单 |
| 角色与动作 → 闲逛：开 / 关 | 切换自动走动 |
| 角色与动作 → 打个盹 / 继续陪你 | 切换休息与唤醒 |
| 躲一会儿 | 隐藏宠物，后台进程继续运行；通过托盘恢复 |
| 回窝啦（退出） | 退出桌面程序，取消尚未确认的操作 |

结果、选项、输入与确认都显示在宠物气泡中。长报告可以滚动，多项选择可以翻页。关闭或取消确认气泡会取消该次未提交操作；已提交的订单需要单独核对或撤单。后台通知会等待正在进行的确认。

宠物上方的进度报告按需通过右键查看；后台活动继续驱动动作。

### 角色与套装

右键 →「角色与动作 → DeepSeek 娘 / ChatGPT 娘」切换角色。DeepSeek 娘支持「默认套装」和「麦麦套装」，选中后保存，下次启动恢复。

「炸薯条 · 循环」会让 DeepSeek 娘穿上麦麦套装并循环播放；「换装」播放切换到另一套衣服的过程，结束后保存新套装。「停止动作」停止当前播放；立即选择套装也可以中止换装。

麦麦套装目前没有独立的跑步、睡眠等素材，相应状态使用穿装待机画面。角色名称与底层标识的对应关系为 `deepseek` → DeepSeek 娘、`maimai` → ChatGPT 娘。动作细节见[动作与皮肤说明](DEEPSEEK-SKINS.md)。

## 在 Agent 中使用

### 通用 MCP 接入

在 McPet 源码或通用 Agent 包目录运行：

```powershell
python -m pip install -r requirements-agent.txt
python -m src.agent_install
```

Windows 便携包使用：

```powershell
.\McPet.exe --install
```

安装器输出 JSON，包含 `server_name`、`server.command`、`server.args` 和技能位置。默认命令只导出连接定义。按宿主的设置界面添加名为 `mcpet` 的 stdio 服务，填写输出的 command 和 args；字段的外层结构以宿主要求为准。

下面是采用 `mcpServers` 容器的配置形状。**占位符需替换成安装器输出值**；便携包的 `args` 为 `[]`：

```json
{
  "mcpServers": {
    "mcpet": {
      "type": "stdio",
      "command": "<server.command>",
      "args": ["<server.args 中的启动器路径>"]
    }
  }
}
```

重新加载项目会话，按宿主要求完成 MCP 信任和工具审批，确认工具列表出现 `mcpet_status`、`mcpet_pet` 等工具。第一条对话可以用：

> 用 McPet 查看当前角色和设置，再切到 DeepSeek 娘的麦麦套装。

宿主负责语言理解与模型调用。McPet 沿用原 Agent 会话，无需另配聊天模型 Key。MCP 接入不会自动启动桌面窗口；需要屏幕上显示宠物时，另行运行桌面入口。

Agent 和桌宠默认共享当前系统用户的 `.mcpet` 数据目录。使用相同 `MCPET_DATA_DIR` 时，已运行的桌宠会读取新的动作与皮肤指令；自定义目录不同会使两者使用独立偏好。

### 可选技能安装

支持项目 `.agents/skills` 的宿主可直接发现源码内的 [.agents/skills/mcpet/SKILL.md](../.agents/skills/mcpet/SKILL.md)。需要复制时，在 McPet 目录运行：

```powershell
python -m src.agent_install --project "<已有目标项目目录>" --skill-dir .agents/skills
```

将 `<已有目标项目目录>` 替换为实际存在的项目；相对技能目录以 `--project` 为基准。宿主使用其他技能位置时，通过 `--skill-dir` 指定其目录。技能提供操作指导，MCP 连接提供执行工具，两项分别安装与加载。

### OpenCode / Claude Code 原生适配

需要原生事件接入时，在 McPet 目录按使用的宿主选择一条命令：

```powershell
python -m src.agent_install --client opencode --project "<已有目标项目目录>"
python -m src.agent_install --client claude --project "<已有目标项目目录>"
```

Windows 便携包将 `python -m src.agent_install` 换成 `.\McPet.exe --install`。指定 `--client both` 可安装两种适配。

OpenCode 安装器写入目标项目的 `opencode.json`、插件和技能；Claude Code 安装器写入 `.mcp.json`、本地 hooks、规则和技能。安装器保留其他服务与已有权限，宿主仍按原生流程处理审批。已存在 `opencode.jsonc` 的项目需要按[技术接入说明](AGENT-HOST.md#可选原生宿主配置)手动合并。

可用 `opencode mcp list` 检查实际连接，用 `claude mcp get mcpet` 检查配置发现。配置发现后，还需要在实际会话中确认工具可调用。

## 账号与本机配置

### 按功能配置凭证

最新源码提供麦当劳、瑞幸公开试用账号。不填写 MCP Token 即可试用在线餐饮查询；查询和明确确认的操作均使用共享账号。长期使用请填写自己的两家 Token，个人配置优先。共享凭证的有效期和服务限流由两家服务决定；失效或限流会直接显示实际错误。

公开的 v0.1.0 下载包保持原版本，需要自行配置餐饮 Token。新的源码发行构建会带 `.env.trial`；保留该文件以加载试用配置。

| 功能 | 需要的配置 | 配置入口 |
|---|---|---|
| 麦当劳优惠、营养查询与订单 | `MCD_MCP_TOKEN` | [麦当劳开放平台](https://open.mcd.cn/mcp) 登录并激活，复制控制台 Token |
| 瑞幸商品与订单 | `LUCKIN_MCP_TOKEN` | [瑞幸官方登录入口](https://open.lkcoffee.com/mcp) 登录后复制 Token |
| DeepSeek 官方余额 | `DEEPSEEK_API_KEY` | 已有 DeepSeek API Key，用于余额只读查询 |
| Orca 额度缓存 | 已配置的本机 Orca 客户端 | 读取已有缓存，显示来源与更新时间 |

桌宠中进入「设置 → 账号凭证」，选择对应项，在遮蔽输入的气泡中填写。留空保留原值；删除凭证使用「账号凭证 → 清除凭证」，再明确确认。凭证只在本机填写，请避免放进 Agent 聊天、Issue 或截图。

仅使用 Agent 时，可通过本机 `.env` 配置，字段见 [.env.example](../.env.example)。将需要的字段写入用户数据目录下的 `.env`；源码用户也可在仓库 `.env` 中填写。已有配置文件先保留原内容，按需添加字段。

配置优先级为 **进程环境变量 → 用户数据目录 `.env` → McPet 项目 `.env` → 公开 `.env.trial`**。麦当劳、瑞幸字段为空或保留占位符时使用共享试用账号。环境变量已有自己的 Token 时，重启仍优先读取它；需要同步修改或清除该变量。桌宠保存凭证后当前进程的后续请求使用新值，其他已运行 MCP 服务需重新加载。

### 数据保存在哪里

默认用户数据目录为 `~/.mcpet`，Windows 中对应当前用户目录下的 `.mcpet` 文件夹。保存内容包括本机 `.env`、角色与位置偏好、营养记录、用量台账和订单审计。

可以使用 `MCPET_DATA_DIR` 指定其他目录，填写实际绝对路径。现行 Python 版本的凭证以本机 `.env` 保存；系统密钥链属于后续参赛版本计划。

日志来源通过「设置 → 日志来源」设置，也可以在 Agent 中指定已存在的 claude / codex / generic 日志目录。桌宠修改日志目录后需重启。日志来源、扫描口径与配置细节见[本机日志桥接](AGENT_BRIDGE.md)。

## 查询优惠与准备餐饮订单

### 麦当劳

1. 配置麦当劳 Token，在「设置 → 时间与位置 → 城市」选择查询城市。
2. 「麦当劳 → 查优惠券」查看券中心与已有优惠券。
3. 需要领取时选择「主动领券」，核对领取范围，在气泡明确确认。
4. 「今天最划算」获取门店和实时报价。桌面入口按当前城市自动选择可用门店，确认前查看显示的门店。
5. 「确认订单」查看门店、餐品、优惠、取餐方式和金额，确认后复核报价并创建订单。当前桌面路径使用外带取餐方式。
6. 「订单付款 → 麦当劳付款」打开或复制已有订单的官方付款链接，由你完成付款。
7. 需要取消时使用「撤销本次订单」，核对订单号并确认；可撤范围取决于官方订单状态。

在 Agent 中也可以先查询并选择真实门店和报价，再准备订单：

> 用 McPet 查上海的麦当劳门店和午餐实时报价。先展示门店、商品、优惠和金额。

> 按刚才选择的门店与报价准备订单，展示确认摘要。

Agent 的准备摘要有 5 分钟有效期；过期或金额变化需要重新准备与确认。门店关键词查询见[门店选择说明](MCD-STORE-SELECTION.md)。

### 瑞幸咖啡

1. 配置瑞幸 Token，在「设置 → 时间与位置」填写经度和纬度。McPet 使用你提供的位置查询门店。
2. 「瑞幸咖啡 → 查找 / 选择门店」查询并选择门店。
3. 「查商品 / 选择咖啡」选择商品，使用「调整规格」设置温度、杯型等选项。
4. 「预览订单」输入数量并查看实付价；商品列表的预估价用于浏览，确认依据预览结果。
5. 「确认瑞幸订单」核对门店、规格、数量与实付，明确确认后创建订单。
6. 「订单付款 → 瑞幸付款」打开官方付款入口；「查订单 / 取餐码」查询订单状态与取餐码。
7. 查询已有其他订单用「查询其他订单」；撤单用「取消已核对订单」，再次确认具体订单号。

在 Agent 中可以说：

> 用 McPet 查瑞幸门店，按我提供的位置选择一家；查询拿铁规格，准备一杯订单并展示实付价。

当前桌面进程新建的瑞幸订单会定时只读查询状态，状态变化时提示取餐码；查询失败、结束、取消或超过一小时后停止自动查询。详细流程见[宠物菜单与瑞幸](PET-MENU-LUCKIN.md)。

### 确认付款与未知结果

默认 OrderGuard 限额为单笔 100 元、每日 3 单，麦当劳与瑞幸共用护栏。确认前展示摘要，提交前再次复核金额；需要重新确认时按新摘要处理。

生成订单后，付款由你在品牌渠道完成。`delivery_unknown` 或「提交结果未知」表示请求结果尚未核实：先到官方 App 查看订单与支付状态，暂停重复创建或撤销。瑞幸的未知提交记录跨重启保留，可能需要人工核查本机记录；请保留记录供排查。

桌面与 Agent 的准备状态分别属于各自进程 / 会话，请在同一个入口完成查询、准备与确认。

## 营养记录

1. 「营养台账 → 选择餐品 / 记账」查询真实餐品并选择。
2. 输入实际食用份数，例如 `1.5`。
3. 核对餐品和份数后确认记账。
4. 「今日营养」查看当天记录和汇总。

Agent 中可以先说「查询巨无霸营养，我吃了 1.5 份」，看到摘要后再明确确认记账。创建订单后仍需按实际食用情况确认记录。营养数值按查询餐品与份数计算，结果可供日常记录参考。

## 工作状态与用量

| 查询 | 数据来源与解释 |
|---|---|
| 会话进度 | 已配置的本机 Claude / Codex / generic 日志，以及可选宿主事件；展示最近状态与是否过时 |
| 本机用量 | 读取到的 token 记录，按时间汇总；首次回填耗时取决于日志量 |
| 账号额度 / 余额 | Orca 已有缓存或配置后的 DeepSeek 官方只读接口；不同窗口、币种独立展示 |

默认日志候选为 `~/.claude/projects`、`~/.codex/sessions`、`~/.mcpet/inbox`，仅使用存在的来源。自定义来源通过设置明确指定。没有来源时显示未知状态，其他本地角色功能仍可用。

查看结果时注意来源、更新时间和 `UNKNOWN` 标记。没有新消息、idle、Stop 或长时间无日志只说明会话状态；任务完成需要日志中明确的完成事件。本机用量受已读日志范围影响，厂商额度与账单按官方口径核对。

普通终端是否显示动画由宿主决定。工具调用可返回动作资源和保存的状态；桌面实际播放需桌宠已启动。

## 提醒设置

在「设置 → 时间与位置」修改饭点与咖啡时间，使用 `HH:MM`，例如 `12:15`。通过「设置 → 自动提醒：开 / 关」控制提醒。

| 触发条件 | 桌面行为 |
|---|---|
| 默认 11:30 饭点 | 提醒；已有麦当劳凭证时只读查券与报价 |
| 默认 15:00 咖啡时间 | 已有瑞幸凭证和所选门店时查询偏好咖啡；未配置时提示设置入口 |
| 活跃会话等待输入或出现错误 | 条件变化时提示查看会话 |
| 已知账号额度使用达到 80% | 条件变化时提醒，按该来源展示额度窗口 |

桌面提醒依赖程序运行；退出后自动查询与气泡停止。Agent 的自动提醒依赖可选原生宿主事件，也可手动询问「用 McPet 检查提醒」。关闭宿主时提醒的送达没有保证。

自动路径仅提醒与查询，领券、创建或取消订单、营养记账仍需你明确确认。Agent 中修改时间可以直接说「饭点改成 12:15，咖啡时间改成 15:30」。

## 可选动作与 GIF 相册

当前源码支持本机导入的早期鲸鲸九姿态，以及录制当前 DeepSeek 娘的全动作 GIF。这些功能在 v0.1.0 发布后加入；完整姿态包和相册按本机素材处理，README 中的展示副本随仓库提供。

- 早期姿态：按 [CeTaPet 来源与导入说明](../assets/cetapet/SOURCE.md)准备素材；装载成功后右键「角色与动作 → 早期鲸鲸姿态」出现相应入口。
- GIF 相册：安装完整依赖，在仓库运行 `python scripts/record_deepseek_gifs.py`。需要额外导出分类文件夹时，使用 `--export "<导出目录>"`。
- Agent 读取：重新加载 MCP 服务后，读取 `mcpet://recordings/deepseek` 获取清单，再按清单中的 URI 读取 GIF。

相册收录当前实际加载的动作，两套皮肤分别录制；静态姿态、别名和复用动画在索引中标注。192 为原尺寸，512 为放大显示版。详细说明见[GIF 小相册](../assets/deepseek-recordings/SOURCE.md)。

## 更新备份与卸载

### 更新或移动安装目录

退出桌宠并停止宿主中的 McPet 服务，备份用户数据目录。新发行包解压到独立目录，保留完整文件结构；重新运行安装器，更新宿主内的 command / args，再重新加载会话。源码用户先处理本地改动，再按自己的 Git 分支更新依赖与源码。

默认用户数据位于安装目录外，重启后继续读取。使用自定义 `MCPET_DATA_DIR` 时，为新进程保留同一个目录设置。备份可能包含凭证、订单与个人记录，请保存在自己控制的位置。

### 卸载

1. 在桌宠菜单选择「回窝啦（退出）」，停止宿主中的 McPet MCP 服务。
2. 在宿主配置中移除 `mcpet` 服务项。使用原生适配时，移除 McPet 专属插件、技能、规则与 `scripts/agent_hook.py` 对应的 hooks，保留其他服务和设置。
3. 删除不再使用的安装目录。源码虚拟环境位于仓库 `.venv`，可随安装目录处理。
4. 按需保留或删除用户数据目录；其中有角色偏好、凭证、营养与订单记录，删除前先备份。

当前提供手动更新与卸载。开机自启动、自动更新和安装签名的产品流程尚未交付。

## 常见问题

| 问题 | 检查与处理 |
|---|---|
| 双击 `McPet.exe` 后没有宠物 | 使用 `Start-Pet.vbs`，或在解压目录执行 `.\McPet.exe --desktop` |
| 启动脚本无反应 | 在 PowerShell 执行桌面命令查看错误；确认完整解压并保留 `_internal` |
| 提示找不到 `src` | 在完整源码 / Agent 包根目录运行模块命令；不要进入 `src` 子目录执行 |
| `No module named PySide6` | 用启动时的同一解释器安装 `requirements.txt`；仅 Agent 接入安装 `requirements-agent.txt` |
| 宿主中没有 McPet 工具 | 核对安装器输出的绝对路径，重新加载会话，完成宿主原生信任流程；技能与 MCP 分别检查 |
| 移动安装目录后连接失败 | 在新目录重跑安装器并更新宿主配置；虚拟环境解释器变动时也需更新 |
| OpenCode 安装器提示已有 JSONC | 按 [Agent 接入说明](AGENT-HOST.md#可选原生宿主配置)手动合并 mcpet 配置与插件 |
| Agent 指令返回成功，桌宠没有变化 | 确认桌宠运行；核对两者的 `MCPET_DATA_DIR`，使用最新服务重新加载 |
| 切换角色后找不到麦麦套装 | 先切到 DeepSeek 娘，该套装属于此角色 |
| 找不到早期姿态或全动作 GIF | 按上节导入 / 录制；v0.1.0 不附带这些本机文件 |
| 查询返回 401 或缺少 Token | 在对应官方入口核对凭证，在本机设置更新，再重载其他已运行服务 |
| 改过设置仍使用旧值 | 检查进程环境变量的优先级；修改日志来源后重启桌宠，其他 MCP 服务重新加载 |
| 瑞幸没有可选门店 | 核对 Token、经纬度与官方返回；先选门店再选咖啡 |
| 没有订单付款入口 | 先确认创建已知订单，检查是否返回付款链接；也可在官方 App 核对 |
| 提交结果未知 | 到官方 App 核对，暂停重复提交；保留未知记录供人工处理 |
| 会话或用量为 UNKNOWN | 核对来源目录存在且有支持的日志；需要时请求刷新，等待首次回填 |
| 余额与本机 token 统计不一致 | 两项来源与范围分别显示，按官方额度 / 余额口径核对 |
| 终端不播放 GIF | 检查宿主图像资源支持；需要桌面播放时显式启动桌宠 |
| 饭点没有提醒 | 检查提醒开关与时间，确认桌宠运行或宿主具备活动事件；核对当天是否已提醒 |
| 隐藏后找不到宠物 | 点击系统托盘的 McPet 图标恢复；同数据目录再次启动桌面入口也会唤醒已有实例 |

问题仍可复现时，提交 [GitHub Issue](https://github.com/songconmaisaix31-design/mcpet/issues)，注明版本 / Commit、系统、桌面或 Agent 入口、宿主名称、复现步骤、预期与实际结果。错误日志、订单信息和截图先脱敏；凭证留在本机。
